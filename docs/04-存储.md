# 04 存储层（Storage）

> 对应 `01-architecture` §4.3（S1~S4）。存储层是「总线之后的服务」：作为事件中心的正式
> 消费方之一，订阅行情/信号/告警/因子事件 → 落盘/DB；同时是**回放源**与**数据服务查询源**。

---

## 1. 定位与边界

```
① 事件中心 ──订阅──► ② 存储进程 ──写──► 存储后端(抽象) ──► CK / duckdb / …
                           │                      │
                           │ 回放查询接口           │ 一等 SQL/文件(直接连后端)
                           ▼                      ▼
                       (回放源给信号引擎/告警)     ⑥ 数据服务(消费方直查)
```

- **存储是正式消费方**（与信号引擎并列，S2）：不「顺手路过」，而是「订阅→写」的一等链路。
  **本层只存行情/信号/因子数据**；配置与目录（交易所、交易对、币、服务器、采集节点）
  属控制面数据库（12），两者不混：catalog 经 `md.meta` 事件进入本层后才可查询。
- **承接 dig3-station 的落盘 / warm-start 职责**（station 已从依赖删除，01 C1）：原始数据落盘
  = 本模块；进程重启后的「最近 N 条」查询 = 本模块 `read_range`（不是采集侧缓存）。
- **回放源 = 存储层**（S3）：不依赖事件中心 backend 的重放能力，也不依赖 dig3 内部文件。
- **查询统一读存储层**（S4）：实时走总线，历史/回放/查询走存储，避免「实时一个数、历史一个数」。

## 2. 抽象层

与事件中心同款套路：**最低公共语义 + 能力后端**。

| 抽象能力 | 契约/接口 | 说明 |
|---|---|---|
| `write(series, batch)` | 追加写入（按 series key + ts） | 消费方进程写，勿从查询面写 |
| `read_range(series, from, to, limit)` | 区间查询（回放/导出/回测用） | 分页、上限 |
| `upsert_by_ts(series, ts, data)` | 按 ts 覆盖写（回补/自愈时覆盖坏档） | 幂等 |
| `query_capabilities()` | 后端能力表：保留/分区/列式/物化视图 | 与事件中心能力表平行 |

不放进抽象 API：事务性（跨后端难保）、全局有序假设、K/V 任意查询。

## 3. 后端

| Backend | 定位 | 适合 |
|---|---|---|
| **ClickHouse**（首选） | 列式分析库 | 大数据量、SQL 一等、信号/因子历史分析 |
| **DuckDB**（候选） | 嵌入式分析 | 单机、更快启动、小数据集/离线导出 |
| Parquet + S3（后补） | 对象存储 + 列式文件 | 归档、深历史 |

- 后端通过 `query_capabilities()` 暴露差异；上层（回放/导出/SQL 面）按能力分支。
- 表结构：沿用既有 PONK 的 ClickHouse DDL 基线（MergeTree + ReplacingMergeTree(x_version) +
  Decimal(38,12) + 分区 + TTL），扩展到 signal/alarm/factor 事件表。列名与 payload 同名（03 §5.3）；`venue` / `market` / `native_code` 来自 `Body::Market`（03 §5.1），心跳、告警、配置类事件表**不设这几列**。

## 4. 回放接口

```
read_range(series, from, to, limit)  → 事件流(与总线事件同格式)
```

- 信号引擎 / 告警 / 因子**回放**（G3 / O / F）：从存储层读，喂进同一 DAG / 规则。
- **回放与实时消费看到同一份标准化数据**（红线 2）。回放不产生「实时和回测两套数」。
- 回放的数据源是**存储层使显式落盘**，即只落「采集发出 → 事件中心 → 存储订阅写入」这一条链
  的事件；不在 dig3 内部文件或总线后端缓存上做回放。

## 5. 一等 SQL/文件导出（数据服务基础，08 详述）

- 消费方直连存储后端（CK / duckdb）执行 SQL。
- 文件导出：按范围导出 CSV / Parquet。
- 鉴权：导出/REST 是数据服务的职责（08），存储只提供读接口。

## 6. 待办 / 需实测

   signal/alarm/factor 表扩展
3. DuckDB 后端适配（嵌入式 vs 独立进程）
4. 回放接口的分页/上限/乱序容忍语义（对接信号引擎回放模式 G3）
5. 保留/TTL 策略（历史多深、冷数据归档）
