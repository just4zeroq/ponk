# 07 因子挖掘（Factor Mining）

> 对应 `01-architecture` §4.6（F1~F3）。因子挖掘模块 = **二级事件源**：订阅原始行情事件，
> 产出**中间量因子事件**；信号引擎把因子事件当普通输入源（与行情事件并列消费）。
> 因子挖掘不依赖信号引擎做任何事——两者只通过事件中心间接耦合（并列，B 模式）。

---

## 1. 定位与边界

```
① 事件中心 ──► md.* ──► ⑤ 因子挖掘(独立进程/模块)
                          │  因子规则(来自控制面 M2)
                          │  计算 → 因子事件
                          ▼
                      ① 事件中心 ──► factor.* ──► ③ 信号引擎(当普通输入)
                                                └──► ⑥ 数据服务(查询/导出)
```

- **并列**（F1）：因子挖掘与信号引擎平级，不强制谁消费它。
- **二级事件生产者**（F2）：输入=原始行情（candle/trade/l1/funding…），输出=中间量因子事件。
- **上游**（F3）：信号引擎把 `factor.*` 当输入之一，与 `md.*` 并列（05 §3 算子输入含因子引用）。

## 2. 因子事件（结构见 03 §5.3，本节只述语义）

**结构定义集中在事件中心协议层**（`FactorEvent`，03 §5.3），各组件共享。

| 字段 | 语义 |
|---|---|
| `factor_id` / `factor_name` | 稳定 ID + 名（如 `btc_funding_discount`、`eth_taker_buy_ratio`） |
| `version` | **因子规则版本**（同名因子 bump 版本时历史可区分） |
| `instrument` / `timeframe` | canonical 标的 + 因子对齐窗口（`1m` / `4h`…） |
| `value` / `meta` | 因子值 + 明细（供偏好/回测/分析） |
| `timestamp` | 交易所时间（ms） |

- 与信号事件**同族**（03 §5.3 一致的 id/name/version/instrument/timeframe/timestamp 结构），
  幂等键语义同 03 §5.4。
- 因子事件落存储层（04 扩展 factor 表），供数据服务查询/导出、信号引擎跑历史因子。

## 3. 因子 vs 信号 / 算子 关系

- **信号算子库里的「因子引用」**指：把 `factor.*` 事件当算子输入（05 §3）。
- **区别**：
  - 因子 = 一套**通用可复用的中间量**（供多个信号/分析共用），独立生命周期、独立版本。
  - 信号 = 面向交易建议的组合（把因子 + 行情组合成 Long/Short/Flat）。
- 边界不锁死：某个量到底是「因子」还是「信号内部中间值」由**使用面**决定——被多处复用的
  提为因子（独立产出），只服务单一信号的留在 DAG 内部。这是配置纪律，不是机制约束。
