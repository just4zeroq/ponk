# 11 桌面客户端（Desktop Client）

> 本文档定义 PONK 的桌面客户端：**行情展示 + 交易所账号管理**。对应 `01-architecture` §2（范围）、
> §3（总体架构）、§6（四条红线），并受 `08-数据服务`（查询面）、`03-事件中心`（协议与接口）、
> `04-存储`（查询源）、`02-采集`（通道与标的）、`09-控制面` §2（八域）约束。
>
> 客户端是**平台的消费端产品**，不是平台的采集/计算/配置节点。它不产生行情、不产生信号、
> 不写配置，因而本文件不含任何 `event_type`、`ConfigDomain`、分片或指派内容。

---

## 1. 定位与边界

### 1.1 是什么 / 不是什么

| # | 判定 | 说明 |
|---|---|---|
| B1 | **是一个只读的行情展示终端** | 消费平台已经产生并落盘的行情数据，做可视化呈现；不采集、不计算、不下发 |
| B2 | **是一个纯本地的凭据保管与展示工具** | 交易所账号凭据的增删改查发生在用户设备上，与平台服务零耦合（§4.2） |
| B3 | **不是一个平台节点（一期）** | 不订阅事件中心、不发 `ops.*` 心跳、不消费任何 `ConfigDomain`（§3.6） |
| B4 | **不是数据服务的实现者** | 它是 `08` 一等 SQL 面的**消费方**，与"分析师直连 ClickHouse"同级 |
| B5 | **不承载配置事实** | 布局、自选列表、主题偏好属**客户端本地偏好**，不进控制面八域（红线 3 约束的是平台业务配置） |

### 1.2 非目标

以下均为**明确不做**，不列入分期：

| # | 非目标 | 依据 |
|---|---|---|
| N1 | 下单 / 撤单 / 订单查询 | `01` §2.2 交易执行排除 |
| N2 | 持仓、余额、资产、盈亏、爆仓价 | `01` §2.2 账户/持仓/资产排除 |
| N3 | 私有行情管线、私有数据接入 | `01` §2.2 |
| N4 | 凭据的上传、同步、托管 | `01` §2.2 密钥管理排除；见 §4.2 |
| N5 | 信号规则 / 告警规则 / 因子规则的配置界面 | 归 `09` 控制面，配置事实来源唯一 |
| N6 | 回放 / 回测操作界面 | 回放源 = 存储层（`04` §4），执行方是信号引擎 |
| N7 | 多用户、账号体系、云同步 | 客户端为单机单用户 |
| N8 | 采集侧能力（订阅计划下发、分片、配额） | `02` §4 / `09` §5 |

### 1.3 与平台的三条边界线

| 边界 | 客户端侧 | 平台侧 | 交接物 |
|---|---|---|---|
| **数据边界** | 只读查询 + 轮询 | 存储后端（`04` §3） | SQL 结果集（含最新值投影，§3.4） |
| **凭据边界** | 本地凭据库 | **无**——平台不接收、不存储、不使用 | 无（不存在交接） |
| **配置边界** | 本地偏好（布局/自选/主题） | 控制面八域（`09` §2） | 无（不存在交接） |

## 2. 技术选型：GPUI + gpui-kit

### 2.1 选型结论

UI 栈固定为 **GPUI（Zed 的 GPU UI 框架）+ gpui-kit（Longbridge 的组件库）**。
`gpui-kit` 为单一入口依赖，内部再分三层：

```text
gpui-kit        应用唯一依赖：钉住 GPUI 版本，并 re-export GPUI / base / component / assets
├── gpui-base        无样式的行为、状态与基础设施（本产品不自建设计系统，故以 component 为主）
└── gpui-component   完整的带样式组件系统
```

## 3. 数据接入方案

### 3.1 问题陈述

`08-数据服务` 已确立三件事：**一等 = SQL / 文件直连存储层**；**二等鉴权 REST 待定（D2）**；
**WS 砍掉（"本期不做外部实时订阅"，不留半成品）**，且 `08` §1 写明"**外部消费者永远看不到总线内部**"。

桌面客户端需要**准实时的行情展示**（自选最新价、当前未收盘 bar、成交流水）。
本节在不破坏 `01` §6 四条红线的前提下给出候选方案与代价。

### 3.2 候选方案总表

| 方案 | 实时性 | 暴露面 | 星型拓扑（红线 4） | 鉴权 / 限流归属 | 对既有决策的关系 |
|---|---|---|---|---|---|
| **A** 客户端直连事件中心 backend，成为总线订阅方 | 最优（总线原生，毫秒级） | **暴露 broker**（Redis/Kafka/NATS/Iggy）及其凭据与网络可达性 | **字面满足**"加节点 = 加订阅方" | 无人负责：需**新设"总线消费凭据"发放与轮换**（当前无此归属） | **推翻 `08` §1「外部消费者永远看不到总线内部」** |
| **B** 存储层轮询 + 最新值投影（一等 SQL 面） | 中（= 存储写入延迟 + 轮询间隔，目标 ≤500 ms） | 暴露存储后端（CK/duckdb），**查询面本就对消费方开放** | **满足**：走红线 4 明文例外（查询面直读存储后端） | **已有归属**：`08` §2 / §5.4「凭据自理（已定）」 | **不推翻** `08`；是 `08` 一等面的直接消费方。需在 `04`/`08` **新增"最新值投影"** |
| **C** 复活鉴权 WS/REST，新增客户端网关 | 近 A（总线 → 网关 → 客户端） | 只暴露网关（broker 留在平台内） | **满足**：网关是新节点，客户端在平台边界之外 | **网关承担**（token 发放/轮换、限流、连接管理）——唯一职责天然自洽的方案 | **推翻 `08` D2「WS 砍掉，不留半成品」** 与 `01` §4.7 D2 |
| **D** 混合：B 承担快照与历史，A 的受控子集承担实时尾部 | 优（尾部走总线） | 暴露 broker（同 A）**且**暴露存储（同 B） | 满足（客户端即订阅方） | 需同时补"总线消费凭据"与存储凭据两套 | **同时推翻** `08` §1 与 `08` §5.4 的单一面假设 |

### 3.3 逐方案代价

#### A. 客户端直连事件中心 backend

- **broker 暴露**：桌面程序运行在用户设备上（可能在内网之外），必须持有 backend 地址、
  凭据与网络可达性。四款 backend 的**按主题/按消费者的细粒度隔离能力差异很大**（`03` §7.1：
  Redis Streams "无分区、无重放"，Kafka 有 ACL，NATS/Iggy 能力"待实测"），**无法假定能按 `md.*` 收窄权限**。
- **消费组语义是隐藏的正确性陷阱**：`03` §3 规定**消费组 = 多个消费者共享消费**，且 `03` §4.4
  **无 ack、读取即推进消费位点**。客户端若并入 `storage` / `signal` 消费组，会**从平台节点手里抢走消息**，
  造成存储缺档、信号漏算。因此客户端**必须独占自己的消费组**——于是每个客户端实例在 broker 侧
  留下一份组状态，晚加入者与 `XTRIM` / retention 裁剪相互冲突（`03` §7.4 明确"保留清理交给 backend 自带策略"）。
- **鉴权与限流无人承担**：`08` §5.4 的"凭据自理"只覆盖**数据服务的查询面**，总线侧消费凭据
  当前**没有任何模块认领**；`09` §2 八域中也没有对应域。
- **实时性**：最优。
- **结论**：**不推荐**（一期）。代价不在延迟，而在"把 broker 交到不可信端点"与"消费组语义被外部端点污染"。

#### B. 存储层轮询 + 最新值投影

- **暴露面**：暴露的是存储后端而非 broker。`08` §2 已把这一面定义为"面向可信消费方
  （分析师/内部系统），鉴权模型简单（内网/凭据）"——**桌面客户端是否算"可信消费方/内网"是待定项**
  （§8.2），需要 `08` 给出判定口径。
- **实时性上限**：存储写入延迟（总线 → 存储进程 → CK）+ 轮询间隔 + 查询耗时。
  分层轮询（§6.3）下，**可见标的 500 ms、后台 5 s** 可达；但**逐笔完整成交流水**与
  **亚秒级五档**无法靠轮询保证不丢。
- **需要新增的投影**：`04` §2 的抽象只有 `write` / `read_range` / `upsert_by_ts` / `query_capabilities`，
  `08` §3 也只列了区间查询。客户端要的是"**每标的最新一条**"——这需要一张**最新值投影**
  （按 `instrument_id` 取最新，`ReplacingMergeTree` + `FINAL` 或物化视图），属 `04`/`08` 的**新增项**。
- **一致性**：天然满足红线 2——历史、回放、客户端看到的是**同一份落盘数据**。
- **结论**：**推荐为一期唯一接入面**（§3.4）。

#### C. 复活鉴权 WS/REST，新增客户端网关

- **需要新造的东西**：网关进程、token 发放与轮换、按客户端限流、连接生命周期管理、
  快照 + 增量协议、断线重连语义、多客户端扇出。`08` §4 明确这些"当前推迟，不设计"。
- **拓扑**：网关成为第 7 个服务节点；它必须订阅总线或读存储，**客户端本身仍在平台边界之外**。
- **鉴权与限流归属**：**网关承担**——四种方案中唯一"职责天然自洽"的。
- **实时性**：近 A。
- **代价**：最高（新进程 + 新协议 + 新鉴权面），且**必须修订 `08` D2 与 `01` §4.7 D2**。
- **结论**：**一期不做**，作为**触发式升级**（§3.4）。

#### D. 混合（B 快照/历史 + A 受控实时尾部）

- 同时承担 A 的 broker 暴露与 B 的存储暴露；需要**两套凭据归属**同时补齐。
- 收益是延迟，代价是把 `08` §1 与 `08` §5.4 一并推翻。
- **结论**：**不推荐**——若真要走总线，直接一步到位选 C 比"半开总线"更干净。

### 3.4 决策与延迟预算

**决策：一期采用方案 B——客户端只经 `08` 一等 SQL 面读存储后端，外加一张"最新值投影"。
方案 C 为触发式升级；方案 A / D 不采纳。**

#### 延迟预算（一期可达性）

| 展示项 | 数据来源 | 目标延迟 | B 是否可达 |
|---|---|---|---|
| 自选列表最新价 / 24h 涨跌 | 最新值投影（ticker） | ≤ 500 ms | **可达** |
| L1 买卖一价 | 最新值投影（`md.l1`，`02` §4：L1 是 ticker 副产品） | ≤ 500 ms | **可达** |
| K 线历史区间 | `read_range` 语义的区间 SQL | 无实时性要求 | **可达** |
| 当前未收盘 bar 跳动 | 最新值投影（`md.candle.1m`） | ≤ 1 s | **可达** |
| 资金费 | 最新值投影 / 区间 SQL | ≤ 5 s | **可达** |
| 逐笔成交流水（完整不丢） | `md.trade` 流 | 完整 | **不可达**——一期降级为"轮询最近 N 条已落盘成交"，界面标注降级 |
| 订单簿五档 | `md.l1` 之外的深度通道 | ≤ 100 ms | **不可达**——且 `01` C4 已定"orderbook 深度仅核心集，一期可不做" |

#### 触发式升级条件

| 触发条件 | 升级到 | 必须同步修订 |
|---|---|---|
| ① 逐笔流水要求完整无丢，或 ② 五档深度进入一期范围，或 ③ 多客户端规模化且轮询对存储构成压力 | **C**（客户端网关） | `08` D2 + `08` §1 + `01` §4.7 D2；`03` §5.3 `NodeKind` 新增网关类型；`09` §2 视网关是否持有配置 |
| 轮询延迟实测持续 > 500 ms 且投影优化无效 | 先评估 C；**仅在 broker 可按主题收窄权限、且"总线消费凭据"有人认领时**才评估 A | `08` §1「外部消费者看不到总线内部」 |

### 4.1 行情展示

| orderbook 深度 | 五档及以上 | 深度视图 | **一期不做**（`01` C4：仅核心集，一期可不做） |

#### 4.1.2 标的与市场

| 项 | 取值 | 依据 |
|---|---|---|
| 首批交易所 | Binance、OKX | `01` C3 |
| 市场 | 现货 + U 本位永续 | `01` C3 |
| 标的集 | **平台控制面白名单的只读投影**——客户端**不做发现、不下发订阅** | `02` §4 |
| Instrument 标识 | canonical `venue:market:native_code` | `02` §3 |
| 扩容 | Bitget / Hyperliquid 随平台扩容 | `01` C3 |

#### 4.1.3 周期口径

平台仅采集 **1m K 线**（`01` C4）。因此 5m / 15m / 1h / 4h / 1d 等周期由**同一份 1m 落盘数据聚合**得到
（存储层 SQL 聚合，或客户端侧对 1m 序列聚合），**不得引入第二数据源**——否则违反红线 2
（实时与查询读同一标准化源）。聚合口径以存储层为准，客户端只做展示层换算。

#### 4.1.4 布局

主区采用可序列化 `dock`：**左 = 自选/标的导航，中上 = K 线，中下 = 成交量/资金费，右 = 盘口与流水，底 = 状态栏**。
布局可保存/恢复/重置（本地偏好，§1.1 B5）。

### 4.2 交易所账号管理

#### 4.2.1 定义：这是**本地凭据库**，不是账户同步

| # | 判定 | 说明 |
|---|---|---|
| A1 | **形态** = 本地凭据库（Credential Vault），**不是**向控制面同步的账户体系 | `01` §2.2 明文排除"密钥管理"；同步即平台承担密钥管理 |
| A2 | **凭据存放在用户设备**：首选操作系统凭据库，降级为加密文件 | 见 §4.2.3 |
| A3 | **不进控制面八域** | `09` §2 八域中只有 `Channels`（告警渠道凭据）含凭据，且其消费者是 `06`；新增"账号域"= 改 `09` §2 |
| A4 | **不进版本化存储** | 控制面是"配置事实来源 + 版本历史 + 审计 + 可回滚"（`09` §4）；把 secret 放进**可 diff、可回滚、可审计留痕**的版本历史是反安全模式 |
| A5 | **非敏感部分也不同步** | 平台无需知道账号存在；venue / 标签 / 启用状态均为客户端本地字段 |
| A6 | 红线 3 不构成约束 | 红线 3 约束**平台业务配置**；`09` §1 已就"引导配置例外"确立同类边界。凭据属**用户私有秘密**，不是平台配置 |

#### 4.2.2 账号条目字段

| 字段 | 敏感度 | 说明 |
|---|---|---|
| `account_id` | 低 | 本地稳定 ID |
| `venue` | 低 | `binance` / `okx` |
| `label` | 低 | 用户自定义备注 |
| `market_scope` | 低 | 适用市场（现货 / 永续）标注，仅作展示提示 |
| `api_key` | **高** | 掩码展示 |
| `api_secret` | **高** | 永不明文回显；编辑即覆盖 |
| `passphrase` | **高** | OKX 需要；同上 |
| `enabled` | 低 | 是否参与自检 |
| `verify_state` / `verify_ts` | 低 | 自检结果（仅 HTTP 状态判定，不保存响应体） |
| `created_ts` / `updated_ts` | 低 | 审计（本地） |

#### 4.2.3 凭据安全方案

| 层 | 措施 |
|---|---|
| **静态存储** | **首选**：操作系统凭据库（Windows Credential Manager / macOS Keychain / Linux Secret Service），经 `keyring` 类 crate 访问。**降级**：加密文件——口令经 KDF（Argon2id 类）派生密钥，AEAD（XChaCha20-Poly1305 类）加密；口令本身来自用户主口令或 OS 凭据库。**排除**：明文文件、平台存储、控制面域 |
| **运行时** | 密钥字段在内存中使用后清零；不写入日志、trace、崩溃转储、诊断导出 |
| **展示** | 默认掩码；揭示需显式动作；复制为一次性显式操作，且提示剪贴板可被其他应用读取 |
| **传输** | **不存在**——凭据不上传平台（A1/A2） |
| **导出** | 仅支持**加密导出**（用户自理）；不提供明文导出，不接入任何同步 |
| **自检** | 可选：向交易所发一次**签名只读校验请求**，**仅判定 HTTP 状态码，响应体即时丢弃**，不解析、不保存任何资产/持仓字段 |

> `gpui-kit` **不提供**任何安全存储能力（§2.5 M21 已核实），该层完全由 PONK 自带。

#### 4.2.4 边界声明

> **本模块不产生任何下单能力。**
> 客户端不实现、不调用、不编译进任何下单 / 撤单 / 订单查询路径；凭据**仅**用于
> §4.2.3 所述的**本地格式校验与可选的只读签名自检**，**不用于签名任何写请求**；
> 平台侧不接收该凭据，因而平台任何节点都不具备使用它的路径。

### 4.3 明确不做（本节内）

- 余额 / 持仓 / 盈亏 / 保证金率 / 爆仓价的任何展示（`01` §2.2 N2）
- 私有行情（账户成交流、仓位变动推送）
- 凭据的云同步、多设备同步、团队共享
- 交易所资产划转、充值提现相关的一切入口

## 6. 数据模型与状态管理

### 6.1 客户端侧类型

| 类型 | 字段（要点） | 来源 |
|---|---|---|
| `InstrumentKey` | `venue` / `market` / `native_code`；canonical = `venue:market:native_code` | `02` §3 |
| `QuoteSnapshot` | `last` / `open_24h` / `high_24h` / `low_24h` / `vol_24h` / `bid` / `ask` / `exchange_ts` / `received_ts` | 最新值投影（`md.ticker` + `md.l1`） |
| `CandleBar` | `ts` / `o` / `h` / `l` / `c` / `v` / `x_version` | `md.candle.1m` |
| `TradeTick` | `ts` / `price` / `size` / `side` / `exchange_ts` | `md.trade`（已落盘窗口） |
| `FundingTick` | `next_ts` / `rate` / `mark` / `index` | `md.funding` |
| `WatchlistEntry` | `InstrumentKey` + 排序位次 + 分组标签 | 本地偏好 |
| `CredentialEntry` | `02` 账号条目字段（§4.2.2） | 本地凭据库 |
| `LayoutState` | dock 序列化结果 | 本地偏好 |
| `PollPolicy` | `visible_interval` / `background_interval` / `hidden_policy` | 本地偏好（可设默认值） |
| `Freshness` | `last_exchange_ts` / `last_query_ts` / `stale` | 派生 |

### 6.2 状态分层与更新路径

| 层 | 内容 | 生命周期 | 是否跨会话 |
|---|---|---|---|
| **运行时行情态** | `MarketStore`：按 `InstrumentKey` 索引的环形缓冲（quote / bar / tick） | 进程内 | 否（重启重建） |
| **连接与轮询态** | `PollScheduler`、`ConnectionState`、`Freshness` | 进程内 | 否 |
| **UI 态** | 当前视图、选中标的、周期、排序、滚动位置 | 进程内，随 `LayoutState` 部分持久化 | 部分 |
| **本地偏好** | `LayoutState` / `WatchlistEntry` / `PollPolicy` / 主题 | 本地配置文件 | 是 |
| **凭据** | `CredentialEntry` | OS 凭据库 / 加密文件 | 是（**唯一跨会话的高敏感态**） |

更新路径：轮询任务在后台完成查询 → 按 `InstrumentKey` 合并进 `MarketStore` → 通过 GPUI 的
`Entity` / `Context` 触发受影响视图重绘。**渲染路径不直接发查询**，查询由调度器统一收敛，
避免高频重绘下的重复请求。

### 6.3 轮询与新鲜度策略

| 策略 | 取值 | 说明 |
|---|---|---|
| 可见集轮询 | 默认 500 ms（可配） | 自选列表与当前打开视图的标的 |
| 后台集轮询 | 默认 5 s（可配） | 非焦点面板、被遮挡的 dock 面板 |
| 隐藏窗口 | 默认暂停（可配降频） | 减少对存储后端的无效查询 |
| 批量 | 单次查询覆盖多标的 | 按 `instrument_id` 批量取最新值，避免 N+1 |
| 失败退避 | 指数退避 + 上限 | 失败不清空已有数据（I6） |
| 新鲜度阈值 | `now - exchange_ts` 超阈值转黄/红 | 状态栏常显 |

### 6.4 精度与时间约定

| 约定 | 内容 | 依据 |
|---|---|---|
| 数值类型 | 价量以**十进制字符串**在链路上传递；存储层为 `Decimal(38,12)`。客户端**不得**在中间环节降级为 `f64` 后再格式化 | `03` §5.5、`04` §3 |
| 展示格式化 | 按标的精度 meta 保留小数位；meta 的获取路径为**开放项**（§8.2） | `02` §3（meta 由控制面在订阅计划下发——客户端不消费该域） |
| UI 库对齐 | `gpui-kit` 提供 `decimal` feature，与上述十进制约定同向 | §2.5 |
| 时间 | 统一毫秒 `u64`；区分 `exchange_ts`（交易所事件时间）与 `received_ts`（观测时间）；新鲜度按 `exchange_ts` 计算 | `03` §5.1 |
| 去重 / 定序 | 普通事件按 `event_id` 语义去重；`candle_1m` 按 bar 起点 + `x_version` 取最新 | `03` §5.4 |
| 序列化 | 客户端不接触总线序列化（`Serialization` 域），只消费 SQL 结果集 | `09` §8 |

### 6.5 本地持久化

| 数据 | 载体 | 备注 |
|---|---|---|
| 布局 / 自选 / 轮询策略 / 主题 | 本地配置文件（JSON 或等价） | 可损坏回退默认 |
| 凭据 | OS 凭据库（首选）/ 加密文件（降级） | §4.2.3 |
| 行情缓存 | **不持久化** | 重启后由查询面重建；避免在客户端落地平台数据副本 |

## 8. 实现事项

> 以下为中性实现条目；**本文件不创建 crate、不改动 `Cargo.toml`、不修改既有文档**。

### 8.1 实现条目

1. **客户端 crate 规划**：独立 crate，与平台 workspace 并列或同 workspace 新增成员；依赖
   `gpui-kit`（精确锁版本）+ 存储查询客户端 + 凭据存储 crate + 签名校验用 HTTP/HMAC 实现。
2. **查询适配层**：区间查询（K 线 / 成交 / 资金费 / 信号回看预留）与**最新值投影**查询的统一入口；
   失败退避、批量合并、新鲜度计算。
3. **行情展示视图集**：自选列表、K 线主图（`CandlestickChart`）、成交量/资金费副图、盘口、
   成交流水（降级模式）、标的检索（命令面板）。
4. **自绘图表层**：十字光标、坐标轴与网格、深度条形、叠加指标线——基于 `plot` 原语
   （`Scale*` / `PlotAxis` / `IntoPlot`）。
5. **账号管理**：本地凭据库（OS 凭据库优先，加密文件降级）、条目 CRUD、掩码输入、
   只读签名自检、加密导出。
6. **主题与本地配置**：明浅深主题、涨跌配色、布局序列化与恢复、轮询策略设置页。
7. **打包分发（Windows）**：MSVC 工具链构建、ZIP 便携包 + Inno Setup 安装包、签名流程、
   干净虚拟机上的安装/卸载/升级验证（`docs/packaging`）。
8. **测试**：`gpui-kit` 的 `test-support` 与 UI 集成测试（无头窗口 + 指针/键盘输入 +
   断言状态/焦点/布局/可访问性）；查询适配层的单元测试；凭据存储的往返与降级路径测试。
9. **未核实项收敛**：按 §2.6 U1~U9 在 Windows 实机上逐条核实并回填本节。
