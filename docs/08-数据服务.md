# 08 数据服务（Data Service）

> 对应 `01-architecture` §4.7（D1~D3）。数据服务是平台对外的查询面：**一等 SQL/文件导出**，
> 二等鉴权 REST 待定，**WS 砍掉（本期不做外部实时订阅）**。

---

## 1. 定位与边界

```
② 存储层(CK/duckdb) ──┬──► ⑥ 数据服务 ──► 一等: SQL直连 / 文件导出(CSV/Parquet)
                      └────────────► 二等: 鉴权 REST(待定)
```

- 消费方直接连存储后端跑 SQL（一等）；CSV/Parquet 导出（一等）。
- 查询**统一读存储层**（红线 2 / S4）——不是总线。外部消费者永远看不到总线内部。
- 二等鉴权 REST：**待定**（D2），不做设计投入。
- **WS 砍掉**：外部实时订阅这层本期不做，不留半成品。

## 2. 一等：SQL / 文件导出

- **SQL 直连**：消费方用 ClickHouse（或 duckdb）的客户端连存储后端，直接用 `SELECT`。
  表结构在 04 §3（沿用既有 PONK ClickHouse DDL 基线 + signal/alarm/factor 扩展表）。
- **文件导出**：按范围导出 CSV / Parquet（供分析师、回测、外部系统）。
- 权限模型：一等 SQL 面向可信消费方（分析师/内部系统），鉴权模型简单（内网/凭据），
  复杂鉴权留到二等 REST。
- **凭据自理（已定）**：消费方身份与凭据的发放/轮换由本模块自管，**不进控制面的配置域**——
  它是数据面访问控制，不是平台配置；控制面只管 `Channels`（告警渠道凭据）等八个域。

## 3. 一等：查询语义

- 统一读存储层 → 查询结果**永远与回放/回测看到的一致**（同一份落盘数据）。
- 支持范围查询（candle 区间、trade 区间、factor 区间、signal 区间、alarm 区间）。
- 不提供「实时 vs 历史」两套查询——实时性走总线/信号引擎，查询永远读落盘后的数据。

## 4. 二等：鉴权 REST（待定）

- 一旦做：带 token / Key 鉴权的标的/区间/聚合查询，读存储层，出站规则=不能反连总线。
- 当前明确**推迟**，不设计。
