# 05 信号引擎（Signal Engine）

> 对应 `01-architecture` §4.4（G1~G5）。信号引擎是平台大脑：把原始行情/因子事件变成
> **可执行建议信号**（multi/short/flat），通过事件中心派发。核心形态：**声明式 RuleGraph
> （DAG）+ 内置算子库（无沙箱），独立进程，一等回放/回测**。

---

## 1. 定位与边界

```
① 事件中心 ──► (md.* + factor.*) ──► ③ 信号引擎(独立进程)
                                       │  规则配置(来自控制面 M2, 拉取/热更新)
                                       │  RuleGraph 实例化 → 算子执行 → 信号事件
                                       ▼
                                   ① 事件中心 ──► signal.* ──► ④ 告警 / 下游
```

- **只算信号，不接执行**（02 §1 / 01 §2.2）：signal.* 派发后，接不接执行是下游的事。
- **哨兵式**：信号 = 配置（YAML/JSON），算子池内置（编译进引擎）。
- **独立进程**（G2）：订阅事件中心的 md.*/factor.* → 算 → 发回 signal.*。独立重启，不打乱采集/存储。

## 2. 规则模型 —— 声明式 RuleGraph

- 一条信号规则 = 一个 **DAG**：节点 = 算子（内置），边 = 数据流（行情/因子/中间值）。
- 配置驱动：新增信号 = 配置组合现成算子（90% 场景）；真溢出 → 加一个 Rust 算子进库。
- **回放一致**（G3）：同一份 DAG 既能消费实时总线事件，也能从存储层历史事件跑 → 同一 DAG
  产出历史信号 → 规则变更可验证（改规则前后同窗信号 diff）。

## 4. 信号事件（结构见 03 §5.3，本节只述语义）

**结构定义集中在事件中心协议层**（`SignalEvent`，03 §5.3）——各组件共享同一份，避免漂移。

| 字段 | 语义 |
|---|---|
| `signal_id` | 稳定 ID，告警规则按它匹配信号 |
| `signal_name` / `version` | 规则名 + **规则配置版本**（新旧信号可区分、可审计） |
| `instrument` | canonical（`venue:market:native_code`，02 §3） |
| `direction` | Long / Short / Flat —— 信号的"建议方向"，**不触发任何执行** |
| `value` | 当前计算值，阈值判定的主判据 |
| `timeframe` | 规则对齐的周期（如 `4h`） |
| `timestamp` | 交易所时间（ms） |
| `payload` | **因子值明细**（如 `rsi: 71.2`）——告警条件引用的字段集 |

- **`payload` 必须带告警可引用的因子值**，否则告警规则和信号算法对不上话（06 §2）：
  告警按 `signal_id` + payload 字段做条件判定。
- 结构新增字段 = 改协议 crate（03 §5.2 变更门槛），仅改算法不动结构则不触发。

## 5. 回放/回测模式（一等功能）

- **实时模式**：消费事件中心 md.*（+ factor.*）→ 喂 RuleGraph → 发 signal.*。
- **回放模式**：从存储层 `read_range` 拉历史事件（与实时同格式，04 §4）→ 喂**同一个 DAG**
  → 产出历史信号序列（可对比、可落回存储层）。
- 回放不依赖总线 backend 重放能力（S3）；回放与实时看到同一份标准化数据（红线 2）。

## 6. 进程生命周期 / 配置热更新

- 独立进程，systemd/手动起停（部署不设计 M3）。
- **配置热更新**：控制面广播 `ctl.config.changed`（03 §8）→ 信号引擎拉取自身规则配置 →
  重建受影响的 RuleGraph；版本号（signal 事件的 `version`）保证信号新旧可区分。
- 信号引擎自己也要上报 `ops.signal` 心跳/指标（延迟/落后/规则数），供 06 副职监控（O2）。

## 7. 幂等 / 状态

- 信号事件同样带 `event_id`（03 §5.4 家族规则）：**身份键 = `instrument_id`**，身份时间 =
  `timestamp`，`signal_id` / `direction` / `version` / `value` 均进入**内容哈希**，故同一标的
  上不同规则、不同方向不会碰撞。信号无 `x_version`（每次推送身份时间都变）。
- **有状态算子**（如状态机/趋势确认）的状态存哪：一期放内存 + 失败重启后从存储层回放重建
  （回放模式顺带解决）；跨进程状态共享（需 Redis 等）二期。
